Nexus Lampe

Wie das Ganze funktioniert

Eine 3D-gedruckte Nexus-Lampe, die blitzt, wenn ein Pull Request landet — auf Schreibtischen, an die niemand herankommt.

Das Problem, das die Architektur bestimmt

Die Lampen stehen in den Wohnungen von Kolleginnen und Kollegen. Hinter fremden Routern, hinter NAT, ohne feste IP, ohne VPN. Nichts von außen kann sie erreichen — ein GitHub-Runner schon gar nicht.

Deshalb dreht die Architektur die Richtung um: jede Lampe baut selbst eine ausgehende Verbindung auf und wartet darauf, dass ihr etwas erzählt wird. CI schickt eine einzige Nachricht an einen Broker, und alle Lampen reagieren. Kein Portforwarding, keine feste Adresse, kein Home Assistant nötig — und es ist egal, ob drei oder dreißig Lampen im Umlauf sind.

Sicherheitsmodell

Die Lampen holen ihre Updates aus fremden Netzen, die URL muss also ohne Login erreichbar sein. Damit ist das Firmware-Image für jeden herunterladbar — alles darin gilt als öffentlich. Die Architektur ist so gebaut, dass das folgenlos bleibt.

Die Trennung ist nicht bloß konfiguriert, sondern nachgewiesen: ein Publish-Versuch mit dem Lampen-Zugang wird vom Broker mit dem Schließen der Verbindung beantwortet. Die Gegenprobe gehört zur Inbetriebnahme.

Entscheidungen, die nicht offensichtlich sind

discover_ip: false
Standardmäßig publiziert ESPHome nach jedem Verbinden seine IP nach esphome/discover/… und abonniert zwei weitere Topics. Alle drei liegen außerhalb der erlaubten Rechte, und ein Broker mit Topic-Rechten beantwortet einen unerlaubten Publish mit dem Schließen der Verbindung. Das Symptom ist irreführend: TLS und Anmeldung gelingen, das Log meldet Connected, eine Sekunde später TCP disconnected, endlos.
topic_prefix: null
Unterdrückt sämtliche Zustands-, Kommando-, Birth-, Will- und Log-Topics. Die Lampen hören ausschließlich zu. Ohne das würden alle Lampen mit identischem Prefix auf demselben Broker übereinander schreiben.
kein Retain beim Publizieren
Eine retained Nachricht bekäme jede Lampe bei jedem Reconnect erneut zugestellt. Ein Router-Neustart würde die ganze Flotte für einen Pull Request von letzter Woche blitzen lassen.
reboot_timeout: 0s
ESPHome startet sonst nach 15 Minuten ohne Broker neu. Wer MQTT nie einrichtet, soll trotzdem eine funktionierende Lampe haben — sie blitzt dann eben nicht.
restore_mode: RESTORE_DEFAULT_ON
Eine USB-Lampe hat keinen Schalter. Einstecken muss Licht bedeuten, und nach einem Stromausfall muss der vorherige Zustand zurückkommen.
Helligkeit auf 45 % gedeckelt
Zehn WS2812B ziehen bei Vollweiß rund 600 mA, mehr als ein USB-Port garantiert liefert. Die Deckelung sitzt unterhalb des Helligkeitsreglers und greift deshalb auch dann, wenn jemand auf 100 % stellt.
Datenleitung auf GPIO4
GPIO16 wäre naheliegend, liegt auf WROVER-Modulen aber am PSRAM. GPIO4 ist auf beiden Varianten frei — eine Unbekannte weniger bei Boards, die wir nie gesehen haben.
zwei Wurzelzertifikate im CA-File
Let's Encrypt ist auf eine neue Wurzel umgestiegen und liefert sie derzeit von ISRG Root X1 quersigniert aus. Beide sind hinterlegt, damit die Lampen den Broker auch dann noch erreichen, wenn die Quersignatur wegfällt.
